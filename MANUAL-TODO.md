# Manual steps for the Student Voice owner

These steps require the owner to use their own account. Complete them privately.

1. **Teacher MFA.** Sign in to `/#staff`, open アカウントのセキュリティ, and select the setup form. Enter your teacher password. Add the displayed key to your authenticator, enter the current code, and store the recovery codes in a password manager. Try signing in from a private browser window before closing the current session. If asked to rotate pre-existing recovery codes, choose 回復コードを更新 and use a fresh authenticator code.
2. **Service-account MFA.** In GitHub, Render, TiDB, and the Google account used for Firebase, open the account security settings. Enable the provider's authenticator or passkey, store its recovery method, and verify from a separate browser session. Avoid putting any recovery code in an issue or log.
3. **Secret storage.** Save the session master and backup key as distinct password-manager entries with access limited to the operator. Use hosting environment variables for the master. Follow `OPERATIONS.md` for rotation. Retain the previous master only for the documented compatibility and backup requirements.
4. **Database network and backup settings.** Review TiDB's Network Access page against Render's documented outbound IP ranges. Use a test service to verify any change before applying it to production. Check backup retention in your TiDB plan. Any paid retention change needs an approved budget. Run the separate restore drill and record aggregate results without student data.
5. **Firebase account deletion after a teacher acts.** Verify the request and resolve the affected Firebase user privately before deleting application data. In Firebase Console, open Authentication → Users, confirm the account, then complete the provider's delete flow. If the student self-deleted and the app reports a pending provider step, verify it there too. The local tombstone prevents the old Firebase account from recreating its Student Voice data.
6. **Retention and enrollment policy.** Approve the data retention proposal in `privacy.html` or replace it with the school's approved wording. Confirm the permitted signup domains before setting `ALLOWED_EMAIL_DOMAINS`. Leave `LEGACY_PASSWORD_CUTOFF` empty until the owner agrees to a date and affected students have a working teacher-assisted recovery path.
